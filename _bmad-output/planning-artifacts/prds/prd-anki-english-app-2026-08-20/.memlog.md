- (decision) Stakes carried over from brief: side product intended to earn revenue. Calibrates PRD to mid rigor — real FRs and metrics, no enterprise ceremony
- (decision) Form factor settled upstream: mobile web PWA for v1
- (event) Concern scan: monetization with metered usage, per-user cost control, voice-data privacy (audio leaves the device to a third-party scorer), mobile IA, and consumer tone. Adapt-In clusters to pull: Platform, Monetization, Constraints and Guardrails (Cost + Privacy), Cross-Cutting NFRs, Information Architecture, Aesthetic and Tone
- (event) Working mode: coaching path, journey-led entry (consumer product, UX-heavy). Section order follows from journeys
- (decision) Scripted-with-conversational-skin chosen over free conversation. Chat-style UI with turn-taking so it FEELS like a conversation, but every user turn has a known reference sentence. Preserves scoring accuracy and TTFW measurability. An explicit End button replaces having to say goodbye
- (decision) Three practice levels REPLACED by a progressive hint ladder. Default state shows nothing — the user must produce the line unaided. Rungs on demand: (1) the situation in which the sentence is used, (2) keywords, (3) the full sentence. Level is no longer a mode the user picks; it is revealed by how far down the ladder they had to go
- (decision) First hint rung is the SITUATION, not the Vietnamese meaning — user's own choice, and pedagogically stronger: showing a translation would reinforce the translate-in-head habit the product exists to break
- (decision) Model audio is NOT a hint rung — it belongs after the attempt, for free self-comparison
- (decision) Hint depth becomes a tracked measure alongside TTFW — 'which sentences still need a hint' is more legible to users than raw latency
- (decision) Home screen shows today's due cards plus, per word, the number of times the user has SUCCESSFULLY PRODUCED that word in practice (active-production count), not review count. New metric, not present in the brief
- (decision) Per-turn scoring inline in the chat flow, automatic — not user-triggered. Verified affordable: ~300 scored attempts/month sits inside the 500 cap. Holds only while retries stay capped at 2-3 per sentence, which the massed-repetition finding already requires
- (assumption) Brief's v1 scope lists three practice levels; the hint ladder supersedes that. Brief will need an update pass once the PRD settles
- (decision) 'Nói ra được' (active production) requires PASSING, not merely uttering: the target word must not be omitted and must score above the accuracy threshold. The home-screen count therefore measures capability, not attempts
- (decision) Hint ladder cut to two rungs — situation, then keywords. The full-sentence reveal is REMOVED: the user is never handed the line to read, so every turn stays a production task
- (decision) Using situation or keyword hints still counts toward 'nói ra được' — the user still had to construct the sentence themselves
- (decision) TTFW is recorded ONLY on turns where no hint was opened. Hinted attempts are discarded from the latency series rather than flagged or re-timed
- (assumption) Measurement artifact to watch: early sessions will produce sparse TTFW data because hint use is high, and the unaided pool grows to include harder sentences over time — average TTFW could drift upward for selection reasons rather than regression. Needs handling in how progress is charted
- (decision) UJ-2 (first-run / onboarding) deferred at the user's request — core loop first. The onboarding EXPERIENCE is deferrable; a minimal vocabulary input path is not, since the core loop cannot run without words in the system
- (event) User signalled a shift toward pace. Staying on coaching for decisions that only he can make, but drafting feature specs myself with assumption tags rather than eliciting section by section
- (decision) v1 keeps reading vocabulary from Anki via the existing AnkiConnect path rather than building a paste/file import first — reuse what already works and spend the effort on the core loop
- (assumption) CONSEQUENCE: AnkiConnect is desktop-localhost-only, so UJ-1 (Son practising on his phone at 5:30am) cannot be exercised on the real target surface until a file/paste import exists. Development and self-testing happen on desktop; UJ-1 validation is deferred with it
- (decision) No user-initiated skip button. Instead the system reveals the correct sentence after repeated failure and marks that sentence for extra repetition — removes the temptation to skip early and takes the decision away from the user
- (decision) Extra repetition after a reveal happens across SUBSEQUENT dialogues, not within the current session — confirmed by the user, consistent with the massed-repetition constraint. Lands in the spacing feature, not the practice-session feature
- (assumption) Reveal triggers after 3 failed attempts on a turn — my proposal, not yet confirmed by the user
- (decision) PRD records that v1 reads from AnkiConnect and that UJ-1 (phone at 5:30am) is therefore a target state, not a buildable one this phase — user accepted this framing
- (event) Azure key supplied and the endpoint verified live from southeastasia, ~1.9s latency. Two code defects found and fixed: the request was missing Dimension:'Comprehensive' (service silently degrades to Basic, returning only AccuracyScore with no ErrorType, Fluency, Completeness or Prosody), and the lab page parsed the SDK-shaped nested response while the short-audio REST API returns scores FLAT on NBest[0] and on each word/phoneme
- (event) Azure does NOT invent errors on correct speech — clean sample scored Pron 96.1 with every word at 100. This is the decisive difference from Gemini, which hallucinated dropped consonants on the same audio
- (event) CALIBRATION FINDING: word-level and summary scores are far too lenient for the dropped-final-consonant errors that matter most for Vietnamese speakers. arrive-for-arrived scored 91 at word level with ErrorType None, walk-for-walked scored 97. But the PHONEME layer separates cleanly: d=0, v=23, t=46 against 100 on the correct reading. Overall PronScore differed by only 1 point between correct and error samples
- (decision) T2 detection (Vietnamese error patterns) must read PHONEME-level scores on word-final consonants directly. Relying on Azure's word AccuracyScore or ErrorType will miss the product's most important error class. This changes FR-15
- (decision) The brief's proposed pass thresholds — word accuracy >= 60, completeness >= 70 — are refuted by measurement: badly mangled words score in the 90s at word level. Thresholds must be defined at the phoneme layer for target words, not the word layer
- (assumption) Test-design caveat carried forward: the first test sentence placed -ed before consonants (walked to, cold drink) where native speakers legitimately do not release the final stop, so Azure scoring 100 there may be correct behaviour rather than a miss. Dialogue generation should prefer contexts where target-word endings are audible, or T2 detection will be unreliable
- (decision) Service division settled: Gemini is NOT replaced. It keeps dialogue generation and gains hint-content generation, Vietnamese feedback prose, and later paraphrase validation. Azure takes two capabilities that previously had no owner — pronunciation scoring and native model audio. What dies is the bidirectional voice MECHANISM, not the vendor
- (decision) Azure also handles TTS rather than Gemini or browser SpeechSynthesis — one key, one bill, and F0 already includes 0.5M characters/month. Browser voices are too robotic for a pronunciation product
- (decision) Hint content is generated in the SAME call as the dialogue and cached. Opening a hint must never make a network call — the user is already stuck at that moment. Added to FR-6
- (decision) Gemini Live path declared dead but NOT deleted yet: keep /practice running until the new practice screen works. Remove useGeminiLive.ts, VoicePractice.tsx and /api/live-token together; /api/live-token is mandatory to remove because it returns the raw GEMINI_API_KEY to the browser. public/audio-processor.worklet.js STAYS — shared recording infrastructure
